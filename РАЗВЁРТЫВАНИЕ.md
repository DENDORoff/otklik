# Развёртывание демо-стенда «Отклик»

Документ отвечает на вопрос «можно ли развернуть проект на Vercel» и описывает,
что уже подготовлено в репозитории, что нужно от оператора и как запустить.

> **Стенд запущен:** https://otklik.deworld.su/ — Vercel (Next.js) + домен
> `otklik.deworld.su` + Neon PostgreSQL (проект `holy-rain-74457731`, ветка `production`).
> Вход администратором (`admin@otklik.local` / `demo1234`) работает, список показывает
> все 21 синтетическое обращение.

---

## 1. Короткий ответ

| Площадка | Подходит | Что мешает |
|---|---|---|
| **Vercel** | **да** | нужна внешняя база данных (SQLite не переживает деплой) |
| Render / Railway / Fly.io | да | те же требования к БД, но можно с диском под SQLite |
| Свой VPS | да | полный контроль, нужны HTTPS и бэкапы |
| GitHub Pages | нет | Pages не запускает Node — статические файлы; весь продукт считается на сервере |

Статическую публикацию на GitHub Pages решено не делать: лендинг и правовые страницы —
часть самого приложения, после деплоя на Vercel они доступны по адресу проекта.

**Что уже сделано в репозитории для Vercel:**

- `otklik/vercel.json` — пресет Next.js, команды установки и сборки, регион `fra1`.
- `otklik/prisma/schema.postgres.prisma` — та же модель данных под PostgreSQL
  (генерируется из `schema.prisma` командой `npm run schema:pg`, вручную не правится).
- `otklik/prisma/migrations/0_init/migration.sql` — начальная миграция для PostgreSQL
  (`prisma migrate deploy`).
- `postinstall` в `package.json` — клиент Prisma генерируется под нужного провайдера:
  SQLite локально, PostgreSQL на Vercel (`DATABASE_PROVIDER=postgresql`).
- `src/lib/storage.ts` — вложения: файловая система локально, Vercel Blob на сервере
  (если задан `BLOB_READ_WRITE_TOKEN`).
- `deploy/vercel.yml` — заготовка workflow для автодеплоя.

**Что нужно от оператора (это нельзя сделать из репозитория):**

1. **Аккаунт Vercel** (бесплатного тарифа хватает) — и один из двух вариантов:
   - *самостоятельно*: `vercel.com/new` → Import Project → репозиторий `DENDORoff/otklik`,
     Root Directory = `otklik`, Framework = Next.js; или
   - *через меня*: создать токен Vercel (Settings → Tokens → Generate, scope: deploy)
     и прислать его — тогда я разверну проект из командной строки.
2. **Внешняя база данных PostgreSQL** — уже подключена: Neon, проект
   `holy-rain-74457731` (организация `org-empty-base-86950343`), ветка `production`.
   Схема применена, синтетические данные залиты. Строки подключения и секрет лежат
   в файле **`otklik/.env.vercel`** (в gitignore) — копируются в Vercel без правок.
   ⚠️ В строке подключения **не должно быть параметра `channel_binding=require`**:
   драйвер Prisma его не понимает и падает с «string contains embedded null».
   Оставляем `sslmode=require`.
3. **Секрет сессии** `AUTH_SECRET` — готов, лежит в `.env.vercel` (отдельный от локального).
4. По желанию — `BLOB_READ_WRITE_TOKEN` для Vercel Blob, чтобы вложения переживали деплой,
   и `BITRIX24_*` для включения интеграции (по умолчанию выключена).

## 2. Пошаговая инструкция (ручной режим)

### Шаг 1. База данных — уже сделано

Neon-проект `holy-rain-74457731` создан и наполнен. Значения для Vercel — в
`otklik/.env.vercel`:

| Ключ в `.env.vercel` | Куда в Vercel | Комментарий |
|---|---|---|
| `DATABASE_URL` | `DATABASE_URL` | пул-ный хост с `-pooler`, `sslmode=require` |
| `DATABASE_URL_DIRECT` | `DATABASE_URL_DIRECT` | прямой хост, для миграций и сида |
| `DATABASE_PROVIDER` | `DATABASE_PROVIDER` | `postgresql` |
| `AUTH_SECRET` | `AUTH_SECRET` | 43 символа, только для сервера |

### Шаг 2. Проект на Vercel

1. `vercel.com/new` → **Add New… → Project** → импортируйте `DENDORoff/otklik`.
2. **Root Directory**: `otklik` (важно — код приложения лежит в подпапке).
3. **Framework Preset**: Next.js (определится автоматически).
4. **Build and Output settings** — всё по умолчанию: Build Command `npm run build`,
   Output Directory `.next`, Install Command `npm ci`.
5. **Environment Variables** — скопировать четыре значения из `.env.vercel`
   (Production + Preview):

   | Переменная | Значение |
   |---|---|
   | `DATABASE_URL` | пул-ный URL Postgres (для рантайма) |
   | `DATABASE_URL_DIRECT` | прямой URL (для миграций и сида, можно не задавать) |
   | `DATABASE_PROVIDER` | `postgresql` |
   | `AUTH_SECRET` | случайная строка ≥ 32 символов (готово в `.env.vercel`) |
   | `NEXT_PUBLIC_SITE_URL` | адрес будущего деплоя (`https://<проект>.vercel.app`) |
   | `BLOB_READ_WRITE_TOKEN` | по желанию, для вложений |

6. **Deploy** — сборка пройдёт: `npm ci` → `postinstall` сгенерирует Prisma-клиент под
   PostgreSQL → `npm run build`.

### Шаг 3. Схема и демо-данные — уже сделано

Миграция применена и синтетические данные залиты на Neon. Повторять не нужно; если базу
пересоздали, команда такая:

```bash
cd otklik
DATABASE_URL="postgresql://ПРЯМОЙ_URL" npm run db:migrate:pg
DATABASE_URL="postgresql://ПРЯМОЙ_URL" npm run db:seed:pg
```

Сид создаёт те же синтетические данные, что и локально: 7 отделов, 24 пользователя,
19 категорий, 18 правил маршрутизации, 21 обращение. Пароль всех демо-аккаунтов — `demo1234`.

### Шаг 4. Проверка

- Откройте `https://otklik.deworld.su/` — лендинг со статистикой.
- Войдите как `admin@otklik.local` / `demo1234` — список из 21 обращения.
- Пройдите сценарий: создать обращение → принять → назначить → выполнить → оценить → закрыть.
- Проверьте, что вложение сохранилось (если задан `BLOB_READ_WRITE_TOKEN`).

### Шаг 5. Домен и метаданные

- Домен `otklik.deworld.su` привязан к проекту Vercel (Settings → Domains).
- Рекомендуется задать `NEXT_PUBLIC_SITE_URL=https://otklik.deworld.su` и передеплоить:
  тогда `canonical`, `sitemap.xml` и Open Graph будут указывать на привязанный домен,
  а не на технический адрес `*.vercel.app`.

## 3. Важные ограничения Vercel

| Тема | Ограничение | Что сделано в проекте |
|---|---|---|
| База данных | файловая система эфемерна, SQLite не подходит | схема и миграция под PostgreSQL готовы |
| Вложения | файлы в `/tmp` исчезают после деплоя | адаптер хранилища: Vercel Blob или локальный диск |
| Статический экспорт | недоступен (Server Actions, база) | не используется; публичная витрина — часть приложения |
| Фоновые задачи | нет очереди | уведомления пишутся в БД, отправка почты имитируется |
| Ограничение времени | Server Actions — до 15 с на плане Hobby | операции короткие, внешние вызовы (Битрикс24) с таймаутом 8 с |
| Регион | Vercel выбирает ближайший регион | зафиксирован `fra1` (Алматы — ближайший) |
| Спиннер/скелетон | стриминг работает, но всё приложение динамическое | скелетоны и `loading.tsx` на месте |

## 4. Автоматическая публикация (CI)

`deploy/vercel.yml` — заготовка workflow для GitHub Actions: она собирает и деплоит проект
по коммиту в `main`. Нужны секреты репозитория:

| Секрет | Значение |
|---|---|
| `VERCEL_TOKEN` | токен Vercel (Settings → Tokens) |
| `VERCEL_ORG_ID` | ID команды/организации |
| `VERCEL_PROJECT_ID` | ID проекта |

Файл workflow копируется в `.github/workflows/vercel.yml` вручную: токен GitHub CLI в нашей
сессии создан без scope `workflow`, поэтому GitHub не даёт закоммитить workflow через него.
Альтернатива — деплой из локального CLI:

```bash
npm i -g vercel
cd otklik
vercel --prod --token $VERCEL_TOKEN
```

## 5. Что НЕ переносится на Vercel

- **Локальная БД** — на сервере она заменяется внешним PostgreSQL; файл `prisma/dev.db`
  в Git не попадает и на сервер не загружается.
- **Журнал безопасности и файлы вложений** остаются в БД/Blob, а не в файловой системе.
- **Статическая публикация на GitHub Pages** отменена: лендинг и правовые страницы живут
  в самом приложении и публикуются вместе с ним на Vercel.
