# Развёртывание проекта «Отклик»

Хакатон завершён, демо-стенд выведен из эксплуатации — репозиторий остаётся как
портфолио. Ниже — полностью самодостаточная инструкция, как развернуть проект заново:
локально за 5 минут, либо в продакшне на Vercel + любой PostgreSQL (например, Neon).

> Быстрый старт локально: `npm install` → `npm run db:reset` → `npm run build` → `npm run start` → `http://localhost:3000`

---

## 1. Локальный запуск (без внешних сервисов)

```bash
cd otklik
npm install          # ставит зависимости и генерирует Prisma Client (postinstall)
npm run db:reset     # создаёт prisma/dev.db, применяет схему и заливает демо-данные
npm run build        # production-сборка
npm run start        # http://localhost:3000
```

- SQLite-схема `prisma/schema.prisma` подхватывается автоматически (`DATABASE_URL="file:./dev.db"`).
- Следующий шаг — `.env.example` → `.env` и при необходимости свой `AUTH_SECRET`.
- Сид создаёт синтетические демо-данные: 7 отделов, 24 пользователя, 19 категорий,
  18 правил маршрутизации, 21 обращение. Пароль всех демо-аккаунтов — `demo1234`.

---

## 2. PostgreSQL вместо SQLite

Проект поддерживает два провайдера через одну переменную `DATABASE_PROVIDER`.

```bash
# сгенерировать PostgreSQL-схему из SQLite-схемы (вручную не правится)
npm run schema:pg

# миграция + сид на целевую базу (убедитесь, что DATABASE_URL указывает на неё)
DATABASE_URL="postgresql://USER:PASSWORD@HOST/DB?sslmode=require" npm run db:migrate:pg
DATABASE_URL="postgresql://USER:PASSWORD@HOST/DB?sslmode=require" npm run db:seed:pg
```

- `prisma/schema.postgres.prisma` — та же модель данных под PostgreSQL.
- `prisma/migrations/0_init/migration.sql` — начальная миграция (`prisma migrate deploy`).
- `postinstall` (`scripts/prisma-generate.mjs`) генерирует Prisma Client под провайдера:
  SQLite локально, PostgreSQL на сервере (`DATABASE_PROVIDER=postgresql`).

## 3. Neon (бесплатная serverless-PostgreSQL)

1. Зарегистрируйтесь на [neon.tech](https://neon.tech) → **New Project** → регион, поближе к серверу.
2. В проекте две ветки: `production` (данные) и, при желании, `preview` для проверки миграций.
3. Возьмите строки подключения (**Connection Details**):
   - `DATABASE_URL` — **pooled**-хост (`-pooler`), для рантайма приложения;
   - `DATABASE_URL_DIRECT` — прямой хост, для миграций и сида (опционально).
4. ⚠️ В строке подключения **не должно быть** `channel_binding=require`:
   драйвер Prisma его не понимает и падает с «string contains embedded null».
   Оставьте `sslmode=require` и добавьте таймауты:
   `?sslmode=require&connect_timeout=10&socket_timeout=15`.

## 4. Vercel

1. `vercel.com/new` → импортируйте репозиторий.
2. **Root Directory** — `otklik` (код приложения в подпапке).
3. **Framework** — Next.js; Build Command `npm run build`, Output `.next`, Install `npm ci`.
4. Переменные окружения (Settings → Environment Variables, Production + Preview):

| Переменная | Значение |
|---|---|
| `DATABASE_URL` | pooled-URL PostgreSQL (для рантайма) |
| `DATABASE_URL_DIRECT` | прямой URL (для миграций/сида; можно опустить) |
| `DATABASE_PROVIDER` | `postgresql` |
| `AUTH_SECRET` | случайная строка ≥ 32 символов (`openssl rand -base64 32`) |
| `NEXT_PUBLIC_SITE_URL` | адрес деплоя (`https://<проект>.vercel.app` или домен) |
| `BLOB_READ_WRITE_TOKEN` | по желанию: Vercel Blob для вложений |
| `BITRIX24_*` | по желанию: включение интеграции (по умолчанию выключена) |

5. Deploy → сборка пройдёт: `npm ci` → `postinstall` сгенерирует Prisma Client под PostgreSQL → `npm run build`.
6. Если база пуста — выполните миграцию и сид против неё (см. § 2).
7. Проверка: `https://<проект>.vercel.app/` → войти `admin@otklik.local` / `demo1234`.

### 4.1. Домен

Settings → Domains → добавьте домен и пропишите его в `NEXT_PUBLIC_SITE_URL`,
передеплойте — тогда `canonical`, `sitemap.xml` и Open Graph будут указывать туда,
а не на `*.vercel.app`.

---

## 5. Вложения (Vercel Blob)

Файлы вложений при заданной `BLOB_READ_WRITE_TOKEN` уходят в Vercel Blob (переживают
деплой); без неё — в `storage/uploads` на диске инстанса (подходит только для локального
стенда). Адаптер — `otklik/src/lib/storage.ts`.

---

## 6. Автодеплой через GitHub Actions

`deploy/vercel.yml` — заготовка workflow: собирает и деплоит проект по коммиту в `main`.
Скопируйте файл в `.github/workflows/vercel.yml` и добавьте секреты репозитория:

| Секрет | Значение |
|---|---|
| `VERCEL_TOKEN` | токен Vercel (Settings → Tokens) |
| `VERCEL_ORG_ID` | ID команды/организации |
| `VERCEL_PROJECT_ID` | ID проекта |
| `DATABASE_URL_DIRECT` | (если нужны миграции в CI) прямой URL PostgreSQL |

Альтернатива без Actions — деплой из локального CLI:

```bash
npm i -g vercel
cd otklik
vercel --prod --token $VERCEL_TOKEN
```

---

## 7. Проверка после деплоя

- Лендинг открывается, в шапке/подвале виден логотип и разделы.
- Вход `admin@otklik.local` / `demo1234` → список обращений.
- Локальный `npm run db:reset` и `db:seed:pg` на серверной базе возвращают одинаковое состояние данных.
- Вложения сохраняются (если задан `BLOB_READ_WRITE_TOKEN`).
- Интеграция Битрикс24 выключена до заполнения `BITRIX24_*` — приложение работает без неё.

## 8. Ограничения площадок

| Тема | Ограничение | Что сделано в проекте |
|---|---|---|
| База данных | файловая система эфемерна, SQLite не подходит | схема и миграция под PostgreSQL готовы (`schema.postgres.prisma`, `migrations/0_init`) |
| Вложения | файлы в `/tmp` исчезают после деплоя | адаптер: Vercel Blob или локальный диск |
| Статический экспорт | недоступен (Server Actions, база) | не используется; публичная витрина — часть приложения |
| Фоновые задачи | нет очереди | уведомления — в БД, email имитируется |
| Зависший запрос | Server Action уходит без клиентского таймаута | сторожевой таймер в UI: через 20 с кнопка разблокировывается («Сервер не ответил…») |
| Недоступная база | запрос мог бы ждать бесконечно | таймаут 10 с на любой запрос Prisma (`src/lib/db.ts`) → понятная ошибка |
| Регион | Vercel выбирает регион | зафиксирован `fra1` в `vercel.json` — измените под свой |
| Спиннер/скелетон | стриминг работает, всё приложение динамическое | скелетоны и `loading.tsx` на месте |

## 9. Переменные окружения

Полный список — `otklik/.env.example`. Обязательные минимум:

- `DATABASE_URL` — строка подключения (`file:./dev.db` локально, `postgresql://…` в проде);
- `DATABASE_PROVIDER` — `sqlite` (по умолчанию) либо `postgresql`;
- `AUTH_SECRET` — ≥ 32 символов, только для сервера.

Опционально: `BLOB_READ_WRITE_TOKEN` (вложения), `BITRIX24_*` (интеграция),
`NEXT_PUBLIC_SITE_URL` (canonical/OpenGraph/sitemap).

## 11. Что НЕ переносится на хостинг

- **Локальная SQLite-база** — в проде заменяется внешним PostgreSQL; `prisma/dev.db`
  в Git не попадает.
- **Журнал безопасности и вложения** — в БД / Blob, а не в файловой системе.
- **Секреты** — только в переменных окружения площадки; в репозиторий не коммитятся.
