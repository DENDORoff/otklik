# «Отклик» — система обратной связи и предложений сотрудников

MVP для хакатона ГК «Модус Трейд». Внутренняя система, в которой сотрудник подаёт
обращение, начальник отдела назначает исполнителя, автор видит итог и оценивает результат.

**Публичный репозиторий:** https://github.com/DENDORoff/otklik
**Живой стенд:** https://otklik.deworld.su/ (Vercel + Neon PostgreSQL)

Документы проекта (концепция, техническая концепция, задачи, чек-лист ТЗ, дизайн-код,
демо-сценарий, итоговый отчёт) лежат в корне репозитория. Контекст для ИИ-агентов —
`AGENTS.md`, аналитический журнал работы — `ИСТОРИЯ-РАБОТЫ.md`.

## Стек

| Слой | Технология | Почему |
|---|---|---|
| UI + сервер | Next.js 15 (App Router), React 19, TypeScript 6 | один процесс, Server Actions вместо отдельного REST-слоя |
| Стили | Tailwind CSS 3 | точное повторение фирменного стиля modus-trade.kz |
| БД | SQLite + Prisma ORM | файл, ноль настройки; переход на PostgreSQL — смена `DATABASE_URL` |
| Авторизация | JWT-сессия в httpOnly cookie (`jose`) + `bcryptjs` | три роли без внешнего провайдера |
| Валидация | zod | проверка каждой формы на сервере |
| Безопасность | rate limit, аудит, CSP и security headers | закрытая админка, лимит попыток, проверка загрузок |
| Аналитика | SQL-агрегаты Prisma + CSS-графики | без тяжёлых зависимостей |

## Быстрый старт

Требуется Node.js 20+ (проверено на 26 LTS).

```powershell
cd D:\DW\hackathon\otklik
Copy-Item .env.example .env   # DATABASE_URL и AUTH_SECRET
npm install
npm run setup     # prisma generate + создание БД + сид из датасета
npm run dev
```

Откройте http://localhost:3000 — откроется страница входа.

> Если PowerShell блокирует `npm`, используйте `npm.cmd` (Execution Policy).
> Полный сброс данных: `npm run db:reset`.

Пароль всех учётных записей — `demo1234`. На странице входа — быстрый вход по отделам:
для каждого отдела две кнопки (руководитель / сотрудник).

| Отдел | Руководитель | Сотрудник |
|---|---|---|
| Продажи | `head.sales@otklik.local` | `sales@otklik.local` |

## Что реализовано (MVP)

- Вход и три роли: сотрудник / начальник отдела / администратор; права проверяются на сервере.
- **Мастер создания из 3 шагов** с прогрессом: тип и категория → описание → срок и отправка.
  Есть «Другое» со своей формулировкой, поиск похожих обращений, согласие на обработку данных,
  проверка файла по имени, MIME и сигнатуре.
- Маршрутизация «категория → отдел» из БД; ответственный — начальник отдела; fallback-очередь
  «Неназначенные» + уведомление администратору. «Другое» всегда идёт в fallback.
- Жизненный цикл: новое → на рассмотрении → ожидает уточнения → в работе → реализовано → закрыто;
  альтернативы: отклонено, дубликат.
- Возвраты: автору на уточнение, исполнителя к начальнику, мотивированный отказ.
- Назначение исполнителя и дедлайна по приоритету (3 / 7 / 14 дней), подсветка просрочки.
- Комментарии, полная история событий (кто, когда, что), уведомления.
- Оценка итога автором (1–5) и закрытие обращения. Необратимые действия подтверждаются модалкой.
- **Список обращений**: вкладки «Все / Мои / На мне / Просроченные», сворачиваемые фильтры,
  поиск, отдельный мобильный список без горизонтальной прокрутки, CSV-выгрузка.
- Аналитика: типы, категории, статусы, доля рассмотренных и закрытых, время первого ответа,
  среднее время решения, просрочка, удовлетворённость, повторяющиеся проблемы.
- **Лента реализованных улучшений** `/improvements` — обезличенные итоги с метриками.
- **Настройки** `/settings`: внутрисистемные и почтовые уведомления, отписка, согласие.
- Справочники: категории, правила маршрутизации, отделы, сотрудники; очередь «Неназначенные».
- **Админка**: запросы по персональным данным (доступ/исправление/удаление/отзыв согласия)
  и журнал безопасности (входы, блокировки, изменения правил, создание обращений).
- **Юридический контур**: политика конфиденциальности, согласие на обработку, условия
  использования, cookie-политика, политика возврата, лицензии; cookie-баннер; форма
  запроса на удаление данных; self-host шрифтов; демонстрационные реквизиты.
- **SEO и доступность**: SSR, title/description/OG/Twitter, JSON-LD, `sitemap.xml`,
  `robots.txt`, skip-link, focus-visible, `aria`-атрибуты, alt-тексты, reduced-motion.
- **Тема оформления**: светлая, тёмная и «как в системе» — переключается в разделе
  «Настройки» (`src/components/appearance.tsx`). Выбор сохраняется в `localStorage` и в cookie
  `theme`, применяется до первой отрисовки, контраст текста ≥ WCAG AA в обеих темах.
- **Языки RU / EN / KZ**: переключатель в разделе «Настройки»; словари
  в `src/lib/i18n`, ключ = русская исходная строка; даты форматируются по локали.
- **Лендинг `/`**: публичная страница с описанием сервиса, шестью шагами процесса,
  возможностями, ролями и статистикой демо-стенда из БД.
- **Липкая шапка**: лого, навигация, уведомления и выход всегда на виду при прокрутке;
  настройки открываются отдельной кнопкой, имя сотрудника — просто подпись.
- **Модуль Битрикс24**: выключен по умолчанию, включается переменными окружения;
  обращение ↔ задача ответственному, вебхук с проверкой секрета.
- **Безопасность**: bcrypt, httpOnly-cookie, лимит попыток входа, rate limit на формы и API,
  CSP и security headers, проверка загрузок, аудит, валидация zod, 404 на чужое обращение.
- Сид: 21 обращение (A-001…A-021, включая дубликат), 19 категорий, 18 правил, 24 пользователя.

## Демо-прогон (проверен 12.11.2026)

Сценарий на 6–7 минут, по ролям. Между шагами можно выходить и входить под другим
демо-аккаунтом — кнопки быстрого входа есть на странице логина.

1. **Администратор** → «Администрирование»: у категории «Интеграции и IT» меняем
   подразделение с «Закупки» на «IT-разработка» → «Сохранить». Здесь же видно журнал
   безопасности и запросы по персональным данным.
2. **Сотрудник** (`purchase@otklik.local`) → «Новое обращение»: три шага с прогрессом.
   Тип, категория «Интеграции и IT» → описание (появляются похожие обращения) →
   приоритет, файл-заглушка, согласие → «Опубликовать». В карточке видно: обращение
   ушло в **IT-разработка**, ответственный — начальник IT.
3. **Начальник IT** (`head.it@otklik.local`) → «Обращения»: «Принять в рассмотрение» →
   «Назначить исполнителя и срок» (дедлайн подставляется по SLA 3/7/14 дней).
4. **Исполнитель** (`it@otklik.local`) → карточка: «Зафиксировать итог и завершить».
5. **Автор** (`purchase@otklik.local`) → карточка: оценка 1–5 → модалка «Оценить и закрыть».
6. **Аналитика** и **«Улучшения»**: доля рассмотренных, время первого ответа, доля с
   результатом, просрочка, удовлетворённость; обезличенная лента итогов.
7. **Бонусы**: вкладки «Мои / На мне / Просроченные», CSV-выгрузка, «Другое» со своей
   категорией → «Неназначенные», «Перенаправить в другой отдел» (лимит 3), «Пометить
   дубликатом», «Отклонить с мотивированным отказом», «Не направлять» в правилах,
   `/settings`, `/data-request`, `/legal/privacy` и cookie-баннер.

> После прогона вернуть чистые данные: `npm run db:reset` (пересоздаст БД из сида).

## Ограничения демо

- Уведомления только внутрисистемные; email-канал имитируется (по ТЗ допустимо).
- Конструктор орг-структуры, интеграции Битрикс24 / 1С, анонимная подача и ML — этап 2,
  описаны в концепции и плане развития.
- Справочники в админке: меняются правила маршрутизации; добавление отделов,
  сотрудников и категорий — через сид (визуальный конструктор — этап 2).
- Реквизиты компании и юридические тексты — демонстрационные, помечены на страницах.
  Перед реальным запуском нужны проверка юристом и уведомление РКН.
- Самостоятельное удаление аккаунта не реализовано: запрос обрабатывает администратор.
- Резервный скринкаст демо не записан — записать перед защитой (T12/T24).
- Все данные синтетические, из предоставленного датасета; реальные сведения компании не используются.

│  │  ├─ data-request/   # запрос на доступ/удаление данных
│  │  ├─ sitemap.ts, robots.ts, opengraph-image.tsx
│  │  └─ globals.css     # фирменные токены и компонентные классы
