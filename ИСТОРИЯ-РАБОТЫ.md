## 1. Исходные условия

Из ТЗ и условий хакатона зафиксировано:

- нужны описания решения **и** демо (п. 4.1), работающий MVP — предпочтителен (п. 4.3);
- использовать **только синтетические данные** предоставленного датасета (п. 3.5);
- интеграции (Битрикс24 / 1С) — только описать, не реализовывать (п. 3.4);
- название **«Сигнал» запрещено**, рабочее имя — **«Отклик»**;
- оформление в стиле `modus-trade.kz`: тёмно-синий `#082742`, красный `#ED1111`,
  шрифт Montserrat, интерфейс и документы на русском.

Ключевые требования продукта: подача обращения, категоризация, маршрутизация к
ответственному, статусы и сроки, комментарии и уточнения, уведомления, фиксация итога,
поиск/фильтры/история, аналитика; роли «сотрудник / руководитель / администратор».

## 2. Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Формат результата | Работающий MVP + документы + демо | Даёт максимум баллов по п. 4.1–4.3 |
| Структура компании | Данные в БД, не хардкод | Демо-бит: админ меняет правило без кода; конструктор — этап 2 |
| Исполнитель | Назначает начальник отдела | Прямое требование ТЗ п. 2.2 |
| Стек | Next.js 15 App Router, React 19, TypeScript 6, Tailwind 3, Prisma 6, SQLite | Быстрый сквозной сценарий, нулевая настройка на демо-машине |
| API | Server Actions вместо REST | Меньше кода, проверка прав рядом с операцией |
| Авторизация | JWT (`jose`) в httpOnly-cookie, пароли `bcryptjs` | Без внешних сервисов, безопасно для демо |
| Маршрутизация | Правило «категория → отдел» + fallback-очередь | Обращения не теряются |
| SLA | high 3 / mid 7 / low 14 дней | Простая и объяснимая модель |
| Дубликаты | Ссылка на оригинал + подписка автора | Профилактика повторов, метрика в аналитике |
| Закрытие | Оценка автора 1–5 | Замыкает цикл, даёт удовлетворённость |

## 9. Итерация 12.11.2026 — тёмная тема с переключением

Задача: «добавим тёмную тему с возможностью переключения».

### 9.1. Решение

- Тема включается классом `.dark` на `<html>`: Tailwind переведён в режим `darkMode: "class"`.
- Палитра вынесена в CSS-переменные (`--color-canvas/surface/subtle/ink/muted/line/info/brand-ink/link`),
  которые переопределяются в `.dark`. Семантические классы Tailwind (`bg-surface`, `text-muted`,
  `border-line`, `text-brand-ink`) ссылаются на переменные — одна точка правки на обе темы.
- Выбор пользователя: `localStorage["theme"]` + cookie `theme` (12 месяцев). Приоритет —
  сохранённый выбор, иначе системная настройка `prefers-color-scheme`.
- Инлайн-скрипт в `<head>` (`themeScript` в `app/layout.tsx`) ставит класс до первой отрисовки —
  вспышки светлой темы нет. `<html>` помечен `suppressHydrationWarning`.
- Переключатель — `components/theme-toggle.tsx` (иконки луна/солнце переключаются только CSS
  `dark:`-вариантами, поэтому рассинхрона гидратации не возникает). Размещён в шапке приложения,
  на страницах `/legal`, `/data-request`, `/login`, на странице 404.
- Cookie темы на сервере не читается: публичные страницы остаются статическими (иначе `cookies()`
  сделал бы всё динамическим).

### 9.2. Что перекрашено

- Компоненты: `.card`, `.btn-secondary`, `.input`, `.field-error`, `.danger-block`, `.skip-link`,
  `.skeleton`, `.legal-prose`.
- Бейджи статусов/приоритетов/типов переведены с inline-стилей на классы `className` в
  `lib/constants.ts` — теперь они учитывают тему (в тёмной «Проблема»/«Предложение»/
  «Положительный отзыв» имеют тёмный фон и светлый текст).
- Служебные блоки: предупреждение о похожих обращениях, прогресс мастера, блоки успеха
  в настройках и `/data-request`, ошибки форм — добавлены `dark:`-варианты.
- Фирменный красный сохранён (`#ED1111`) для акцентов; для заливки кнопок введён
  `brand.action = #E10F0F` — белый текст на нём проходит WCAG AA (4.9:1), на `#ED1111` было 4.48:1.

  Для этого приглушённый серый `#64748D` заменён на `#5C6675`, а ссылка `#E40000` — на `#D40000`.

## 15. Итерация 13.11.2026 — подготовка деплоя на Vercel

Вопрос: «можно ли развернуть демо-проект на Vercel и что для этого нужно».

### 15.1. Разбор

- Vercel запускает Node и поддерживает Server Actions — само приложение переносится без
  изменений кода.
- Блокирующее ограничение — база: файловая система на Vercel эфемерна, SQLite не подходит.
  Нужен внешний PostgreSQL (Neon, Supabase, Vercel Postgres).
- Второе ограничение — вложения: они лежат в `storage/uploads`, на сервере их нужно хранить
  в объектном хранилище (Vercel Blob).

### 15.2. Что сделано в репозитории

| Файл | Назначение |
|---|---|
| `otklik/prisma/schema.postgres.prisma` | та же модель данных под PostgreSQL; генерируется из `schema.prisma` (`npm run schema:pg`) |
| `otklik/prisma/migrations/0_init/migration.sql` | начальная миграция для PostgreSQL (`prisma migrate deploy`) |
| `otklik/scripts/prisma-generate.mjs` | генерация клиента Prisma под провайдера: SQLite локально, PostgreSQL при `DATABASE_PROVIDER=postgresql`; вызывается в `postinstall` |
| `otklik/src/lib/storage.ts` | хранилище вложений: локальный диск или Vercel Blob (`BLOB_READ_WRITE_TOKEN`) |
| `otklik/vercel.json` | пресет Next.js, команды установки и сборки, регион `fra1` |
| `otklik/.env.example` | новые переменные с комментариями |
| `deploy/vercel.yml` | заготовка workflow для автодеплоя |
| `РАЗВЁРТЫВАНИЕ.md` | инструкция: что подготовлено, что нужно от оператора, ограничения Vercel |

Сид (`prisma/seed.js`) провайдер-независим: те же синтетические данные на PostgreSQL.

### 15.3. Что нужно от оператора

1. Аккаунт Vercel: либо импорт репозитория вручную (Root Directory = `otklik`),
   либо токен Vercel — тогда деплой делается из командной строки.
2. Внешний PostgreSQL: прямой и пул-ный `DATABASE_URL`.
3. `AUTH_SECRET` (случайная строка ≥ 32 символов).
4. По желанию — `BLOB_READ_WRITE_TOKEN` и переменные `BITRIX24_*`.

### 15.4. Проверки

- `prisma validate --schema prisma/schema.postgres.prisma` — схема валидна.
