## 1. Исходные условия

Из ТЗ и условий хакатона зафиксировано:

- нужны описания решения **и** демо (п. 4.1), работающий MVP — предпочтителен (п. 4.3);
- использовать **только синтетические данные** предоставленного датасета (п. 3.5);
- интеграции (Битрикс24 / 1С) — только описать, не реализовывать (п. 3.4);
- название **«Сигнал» запрещено**, рабочее имя — **«Отклик»**;
- оформление в стиле `modus-trade.kz`: тёмно-синий `#082742`, красный `#ED1111`,
  шрифты Gilroy / Montserrat, интерфейс и документы на русском.

Ключевые требования продукта: подача обращения, категоризация, маршрутизация к
ответственному, статусы и сроки, комментарии и уточнения, уведомления, фиксация итога,
поиск/фильтры/история, аналитика; роли «сотрудник / руководитель / администратор».

## 2. Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Формат результата | Работающий MVP + документы + демо | Даёт максимум баллов по п. 4.1–4.3 |
| Структура компании | Данные в БД, не хардкод | Демо-бит: админ меняет правило без кода; конструктор — этап 2 |
| Исполнитель | Назначает начальник отдела | Прямое требование ТЗ п. 2.2 |
| Стек | Next.js 15 App Router, React 19, TypeScript 6, Tailwind 3, Prisma 6, SQLite | Быстрый сквозной сценарий, нулевая настройка на демо-машине |
| API | Server Actions вместо REST | Меньше кода, проверка прав рядом с операцией |
| Авторизация | JWT (`jose`) в httpOnly-cookie, пароли `bcryptjs` | Без внешних сервисов, безопасно для демо |
| Маршрутизация | Правило «категория → отдел» + fallback-очередь | Обращения не теряются |
| SLA | high 3 / mid 7 / low 14 дней | Простая и объяснимая модель |
| Дубликаты | Ссылка на оригинал + подписка автора | Профилактика повторов, метрика в аналитике |
| Закрытие | Оценка автора 1–5 | Замыкает цикл, даёт удовлетворённость |

### 3.2. Проектирование

- Схема БД: `departments`, `users`, `categories`, `routing_rules`, `appeals`,
  `appeal_history`, `comments`, `notifications`, `attachments`, подписки на дубликаты.
- Жизненный цикл: Новое → На рассмотрении → (Ожидает уточнения ↔ На рассмотрении) →
  В работе → Реализовано → Закрыто; ветки «Отклонено» и «Дубликат».
- Матрица прав: сотрудник — свои; начальник — отдел + личные; админ — всё.
- Правила уведомлений по событиям жизненного цикла.

### 3.3. Реализация MVP (`otklik/`)

- Каркас Next.js, Tailwind, брендированные компоненты (`logo`, `nav`, `badges`).
- Вход/выход, три роли, быстрый вход кнопками на `/login`.
- Список обращений: фильтры по статусу, категории, отделу, типу, приоритету,
  просрочке; поиск; метка «просрочено».
- Создание: тип, категория, приоритет, описание, предложение решения, вложение до 5 МБ;
  автоматический номер `A-XXX`.
- Карточка: история, комментарии, запрос уточнения и ответ автора, назначение
  исполнителя и срока, фиксация итога, отказ с причиной, перенаправление, дубликат,
  оценка 1–5.
- Уведомления и «прочитать всё».
- Аналитика: метрики ТЗ п. 2.7 (доля рассмотренных, время первого ответа, доля с
  результатом, удовлетворённость, просрочка, дубликаты, разрезы).
- Админка: правила маршрутизации, справочники, пользователи, очередь «Неназначенные».
- Брендированные `not-found.tsx` (404 на русском) и `error.tsx`.

### 3.4. Отладка окружения

| Проблема | Решение |
|---|---|
| PowerShell блокирует `npm.ps1` (Execution Policy) | использовать `npm.cmd` |
| TypeScript 7 несовместим с Next 15 | зафиксирован `typescript@^6` |
| Алиас `@` не резолвился | убран `baseUrl`, alias продублирован в `next.config.mjs` |
| Нет типов для CSS-модулей | `src/types/assets.d.ts` |
| Большие вложения | `bodySizeLimit: "5mb"` в Server Actions |
| SQLite не поддерживает enum | статусы/типы/приоритеты — строки + константы в `src/lib/constants.ts` |
| `npm run db:reset` возвращает код 1 | сид при этом успешен; `db:seed` и `db:push` по отдельности дают 0 |

### 3.5. Проверка и найденные баги

- **Баг:** пункт «Не направлять» в правилах маршрутизации ничего не делал.
  **Исправление:** пустой `departmentId` деактивирует правило (`updateMany` + `isActive: false`),
  обращение уходит в очередь «Неназначенные», админ получает уведомление
  (`src/app/(app)/admin/actions.ts`).
- **Баг:** чужое обращение по прямой ссылке отдавало стандартную английскую 404.
  **Исправление:** брендированные `src/app/not-found.tsx` и `src/app/error.tsx`.
- Проверено на production-сборке: смена правила → A-022 ушло в IT-разработку →
  принять → назначить (SLA 14.11) → выполнить → оценить 5 → закрыто.
- Проверены: уточнение и ответ автора, отказ, перенаправление (A-007 → IT, `redirectCount = 1`),
  дубликат A-020 → A-004 с подпиской, уведомления, фильтры (просрочка A-003, A-009),
  вложение `demo-материал.txt`, fallback-очередь, 404 на чужое обращение.
