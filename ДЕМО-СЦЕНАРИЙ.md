# Демо-сценарий защиты (6–7 минут)

Работающий MVP «Отклик». Ниже — тайминг, точные клики и запасные варианты.
Сценарий прогнан на production-сборке 11.11.2026.

## Перед выходом (2 минуты)

```powershell
cd D:\DW\hackathon\otklik
npm run db:reset      # чистые данные из датасета
npm run build
npm start             # http://localhost:3000
```

- Открыть браузер на `http://localhost:3000/login`, масштаб 100–110%.
- Проверить, что виден список из 21 обращения и аналитика считается.
- Держать открытыми: вкладку с приложением и папку `screenshots/` (резерв).
- Пароль всех аккаунтов — `demo1234`; на логине есть кнопки быстрого входа.

## Тайминг

### 0:00–0:30 · Вход и проблема

Войти как **администратор** (кнопка «Администратор»).

> «Сотрудник видит проблему или идею, но не знает, кому её передать. Руководитель не видит
> поток обращений. Компания теряет улучшения. «Отклик» доводит каждое обращение до итога:
> подача → маршрутизация → исполнитель → результат → оценка автора».

### 0:30–1:30 · Структура компании — это данные

«Администрирование» → у категории **«Интеграции и IT»** сменить подразделение
с «Закупки» на **«IT-разработка»** → «Сохранить».

> «Мы не переписываем код под каждое изменение структуры. Правило маршрутизации — запись
> в базе. Полный конструктор отделов — этап 2, но ключевой принцип уже работает».

### 1:30–2:30 · Сотрудник подаёт обращение

Выйти → войти как **сотрудник закупок**. «Новое обращение»:

- тип «Проблема», категория **«Интеграции и IT»**, приоритет «Высокий»;
- описание: «Повторный ввод данных в разных системах занимает много времени»;
- предложение решения: «Синхронизировать справочник контрагентов»;
- вложение — любой текстовый файл-заглушка → «Опубликовать».

В карточке показать: номер **A-022**, отдел **IT-разработка**, ответственный —
руководитель IT. Это результат смены правила 30 секунд назад.

### 2:30–3:30 · Начальник отдела берёт в работу

Выйти → войти как **начальник IT** → «Входящие» → открыть A-022.

- «Принять в рассмотрение»;
- «Назначить исполнителя и срок» → выбрать сотрудника → дата подставлена
  по SLA (высокий — 3 дня) → «Взять в работу».

> «Исполнителя назначает начальник отдела, а не автор — это ТЗ п. 2.2. Срок зависит
> от приоритета, просрочка подсвечивается».

### 3:30–4:15 · Исполнитель фиксирует итог

Выйти → войти как **IT-специалист** → открыть A-022 → «Зафиксировать итог
и завершить» → описать результат → «Отметить выполненным».

> «Виден итог и предпринятые действия. Автор получил уведомление».

### 4:15–4:45 · Автор оценивает и закрывает

Выйти → войти как **сотрудник закупок** → открыть A-022 → оценка **5** →
«Оценить и закрыть».

> «Цикл замкнут: обращение закрыто, оценка попала в аналитику».

### 4:45–5:45 · Бонусные механики (по одному клику)

На уже готовых данных сида:

- **Уточнение**: A-005 — «Ожидает уточнения», в истории запрос и ответ автора.
- **Мотивированный отказ**: A-017 — причина видна автору.
- **Дубликат**: A-021 — ссылка на A-004, автор подписан на оригинал.
- **Перенаправление**: A-007 (если не сбрасывали данные) — история маршрута;
  лимит 3 перехода, дальше эскалация администратору.
- **Очередь «Неназначенные»**: админ → «Не направлять» у категории → новое
  обращение не теряется, а попадает в очередь и админу приходит уведомление.

### 5:45–6:30 · Аналитика

«Аналитика»: всего 21, доля рассмотренных, доля с результатом, время первого
ответа, среднее время решения, удовлетворённость, просрочка, дубликаты,
разрез по типам/категориям.

> «Это метрики ТЗ п. 2.7. Руководитель видит не поток жалоб, а управляемую картину».

### 6:30–7:00 · Границы и развитие

> «Что реализовано: полный жизненный цикл, роли, маршрутизация из БД, SLA,
> уведомления, аналитика. Что имитация: email-канал — внутрисистемные уведомления.
> Что дальше: конструктор структуры, интеграции Битрикс24/1С, анонимные опросы,
> ML-подсказки похожих обращений. Данные — только синтетические из датасета».

## Если что-то пошло не так

| Ситуация | Действие |
|---|---|
| Не работает создание | Открыть готовое A-003 (в работе) или A-002 (на рассмотрении) — показать действия на нём |
| Не успели назначить | Показать A-009 (в работе, дедлайн, исполнитель) |
| Не считается аналитика | Показать скриншот `screenshots/04-analytics.jpeg` |
| Сервер не поднялся | Показать скриншоты 01–05 и продолжить по ним |
| Сброс данных | `npm run db:reset` (30 секунд), войти заново |

## Вопросы жюри — короткие ответы

**Почему не конструктор структуры?** Структура уже данные: отделы, сотрудники,
категории и правила лежат в БД и меняются без кода. Визуальный редактор дерева —
этап 2; на MVP важнее сквозной процесс.

**Куда падают обращения без правила?** В очередь «Неназначенные» у администратора,
автор получает статус, админ — уведомление. Ничего не теряется.

**Как не утонуть в дублях?** Пометка дубликата со ссылкой на оригинал, подписка
автора на обновления, счётчик повторов в аналитике.

**Почему SQLite?** Нулевая настройка для демо; Prisma меняет провайдер на
PostgreSQL одной строкой. Для пилота этого достаточно.

**Безопасность?** Пароли — bcrypt, сессия — подписанный JWT в httpOnly-cookie,
права проверяются на сервере в каждом действии, чужие обращения недоступны (404).

**Как измерять пользу?** Доля рассмотренных, время первого ответа, доля обращений
с результатом, удовлетворённость, число реализованных улучшений.
