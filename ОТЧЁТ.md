# Отчёт по проекту «Отклик»

**Хакатон:** ГК «Модус Трейд» · внутренняя система обратной связи и предложений сотрудников
**Дата:** 12 ноября 2026
**Репозиторий:** https://github.com/DENDORoff/otklik
**Код:** `otklik/` · **Документы:** корень репозитория · **Скриншоты:** `screenshots/`

> Рабочее имя — **«Отклик»**. Название «Сигнал» не используется по условиям хакатона.

---

## 1. Кратко

Сделан работающий MVP, который закрывает сквозной процесс:

**подача → маршрутизация по категории → начальник отдела → исполнитель → итог →
оценка автора → закрытие**

Три роли (сотрудник, начальник отдела, администратор), полный жизненный цикл,
SLA 3/7/14 дней, уточнения, отказ, перенаправление, дубликаты, аналитика,
лента улучшений, админка, юридический контур, SEO и базовая безопасность.

Проверено на production-сборке 12.11.2026: сборка без ошибок типов, 24 маршрута,
сквозной прогон ролей, мастер создания, CSV, модалки, запросы ПДн, журнал, мобильная
ширина без горизонтального скролла.

## 2. Что реализовано

### 2.1. Продукт и процесс

| Блок | Реализация |
|---|---|
| Вход | Почта + пароль, быстрый вход для демо, выход, лимит 5 попыток / 15 минут |
| Роли | Сотрудник — свои; начальник — отдел + личные; админ — всё |
| Создание | Мастер из 3 шагов, тип, категория, «Другое», приоритет, описание, решение, файл, согласие |
| Похожие | `/api/similar` — 4 доступных обращения по тексту, обновление по мере ввода |
| Маршрутизация | Правило «категория → отдел» из БД; нет правила → «Неназначенные» + уведомление админу |
| Исполнитель | Назначает начальник отдела, дедлайн по SLA, просрочка подсвечивается |
| Цикл | Новое → На рассмотрении → Ожидает уточнения ↔ На рассмотрении → В работе → Реализовано → Закрыто; Отклонено, Дубликат |
| Возвраты | Уточнение автору, возврат исполнителя, мотивированный отказ |
| Перенаправление | Лимит 3, затем эскалация администратору, история маршрута |
| Дубликаты | Ссылка на оригинал, подписка автора, счётчик повторов |
| Оценка | 1–5, закрытие обращения, средняя удовлетворённость в аналитике |
| Список | Вкладки «Все / Мои / На мне / Просроченные», сворачиваемые фильтры, поиск, мобильный список |
| Выгрузка | CSV с BOM, защитой от формул Excel и rate limit |
| Уведомления | Внутрисистемные, счётчик непрочитанных, «прочитать всё» |
| Аналитика | Типы, категории, статусы, доля рассмотренных/закрытых, первый ответ, среднее решение, просрочка, удовлетворённость |
| Улучшения | `/improvements` — обезличенная лента итогов и метрик |
| Настройки | `/settings` — уведомления, отписка, согласие, ссылка на запрос данных |
| Админка | Правила маршрутизации, отделы, пользователи, очередь, ПДн-запросы, журнал безопасности |

### 2.2. UX и интерфейс

- Мастер с прогрессом «Шаг N из 3», подсказки, счётчик символов, ошибки рядом с полем.
- Выбор параметров — выпадающие списки; необратимые действия — модалка подтверждения;
  остальные — кнопка с pending-состоянием.
- Три уровня отступов (8 / 24 / 64–96), ограниченная ширина текста, сканируемые абзацы.
- Явный primary CTA на каждом экране, secondary — рядом, без конкуренции.
- Скелетоны вместо спиннеров (`loading.tsx`), 4 состояния действий: loading / empty / error / success.
- Пустые состояния с объяснением и действием; ошибки не винят пользователя.
- «Читать далее» для длинных описаний и итогов.
- Мобильная вёрстка: отдельный список без горизонтальной прокрутки, доступный CTA,
  проверено на ширине ~418 px; брейкпоинты 390 / 768 / 1440 заложены в Tailwind.
- Контраст текста, focus-visible, skip-link, alt-тексты, reduced-motion.
- Светлая и тёмная тема с переключателем в шапке: выбор запоминается (localStorage + cookie),
  применяется до первой отрисовки, аудит контраста WCAG AA в обеих темах — 0 нарушений.
- Липкая шапка: лого, навигация, переключатель темы и уведомления всегда на виду при прокрутке.
- Языки RU / EN / KZ: переключатель в шапке, переведены интерфейс, даты и подписи.
- Публичный лендинг `/`: первый экран, шесть шагов процесса, возможности, роли,
  статистика демо-стенда из БД, дорожная карта, ограничения.
- Бренд: `#082742`, `#ED1111`, Montserrat self-host, интерфейс на русском.

### 2.3. Юридический контур и персональные данные

- `/legal/privacy` — политика конфиденциальности.
- `/legal/consent` — согласие на обработку ПДн с версией.
- `/legal/terms` — условия использования.
- `/legal/cookies` — cookie-политика; cookie-баннер с выбором «только необходимые / принять все».
- `/legal/refund` — политика возврата (для демо-стенда).
- `/legal/licenses` — лицензии шрифтов (Montserrat OFL), кода и изображений.
- `/data-request` — запрос на доступ, исправление, удаление или отзыв согласия; ответ до 10 рабочих дней.
- Согласие фиксируется в `User.consentVersion/consentAt`; в формах есть обязательные чекбоксы.
- В админке — обработка запросов ПДн и журнал безопасности.
- Реквизиты компании помечены как демонстрационные; реальные данные не используются.
- Отписка от необязательных уведомлений одной кнопкой; сервисные сообщения остаются.
- Никаких тёмных паттернов, скрытых комиссий, фейковых отзывов и неподтверждённых заявлений.

### 2.4. SEO и производительность

- SSR/пререндер публичных страниц, `title`/`description` для каждого экрана.
- Open Graph и Twitter Card, изображение `opengraph-image.tsx`, favicon `icon.svg`.
- JSON-LD организации, `sitemap.xml`, `robots.txt` с закрытием приватных разделов.
- Self-host шрифтов, без внешних SDK и аналитики; CSS-графики без тяжёлых библиотек.
- Компактный First Load JS ~103–111 kB на маршрут.

### 2.5. Безопасность

- Пароли — bcrypt; сессия — подписанный JWT в httpOnly-cookie, `sameSite=lax`.
- `AUTH_SECRET` обязателен в production (минимум 24 символа).
- Лимит попыток входа, rate limit на создание обращений, API похожих и CSV.
- Все права проверяются на сервере в Server Actions, не только в UI.
- Zod-валидация каждой формы; параметризованные запросы Prisma.
- CSP, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`,
  `Permissions-Policy`, HSTS в production.
- Проверка загрузок: размер, имя, MIME, сигнатура; исполняемые файлы запрещены.
- 404 на чужое обращение; закрытая админка; аудит входов и чувствительных действий.
- `.env`, `dev.db`, `node_modules`, `.next`, `storage/uploads` не попадают в Git.

## 5. Ограничения и честные границы

- Уведомления только внутрисистемные; email имитируется.
- Конструктор отделов/сотрудников — этап 2; сейчас справочники меняются сидом.
- Интеграции Битрикс24 и 1С описаны, но не реализованы.
- Юридические тексты и реквизиты — демонстрационные, требуют проверки юристом.
- Уведомление РКН и назначение ответственного за ПДн — организационные шаги.
- Самостоятельное удаление аккаунта не реализовано: запрос обрабатывает администратор.
- Резервный скринкаст демо не записан.
- ML-подсказки похожих обращений — план развития; сейчас поиск по вхождению текста.
